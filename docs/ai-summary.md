# ИИ-резюме состава («Коротко о составе»)

После разбора состава на странице `/analyze` появляется блок «Коротко о составе»: одна фраза-итог
и три коротких абзаца («Что внутри», «Кому подойдёт», «На что обратить внимание»). Его пишет Gemini.

## Как это работает

1. Разбор идёт как раньше: только по базе Buty, мгновенно, без ИИ.
2. Затем страница отдельно запрашивает `POST /api/analyze/summary { text }`. Сервер ещё раз разбирает состав по базе
   и передаёт в Gemini **только факты из базы**: ингредиенты по порядку, категории, функции, доказательность, флаги
   и конфликты. Ни текст с упаковки, ни нераспознанные слова, ни данные пользователя в ИИ не уходят.
3. Ответ проходит проверку (`lib/ai-summary/validate.ts`): формат, длина, запрещённые формулировки
   («лечит», «избавит», «токсичный», беременность, дети, ссылки).
4. Ответ сохраняется в таблицу `AiSummary`. Ключ — отпечаток набора ингредиентов по порядку. Тот же крем у другого
   пользователя получает резюме из кэша мгновенно и бесплатно.
5. Резюме не пишется, если распознано меньше 3 ингредиентов или меньше половины состава.

Защита бюджета: не больше 30 новых обращений к ИИ в час с одного IP и 2000 в сутки на весь сайт
(`AI_SUMMARY_DAILY_LIMIT`). Ответы из кэша в лимиты не входят. Если ключ не задан, ИИ недоступен или
лимит исчерпан, вместо ИИ-резюме показывается **сводка по правилам** из данных базы
(`buildBasicSummary` в `lib/analysis/basic-summary.ts`): акцент состава, основа и активы, кому подойдёт,
на что обратить внимание (конфликты, отдушки, комедогенность, Malassezia, неполное распознавание).
Блок «Коротко о составе» есть всегда — с ИИ или без. Разбор от этого не ломается.

## Запуск по шагам

### Шаг 1. Ключ Gemini
1. Откройте https://aistudio.google.com/apikey (тот же Google-аккаунт, что и для Vision).
2. «Create API key» → выберите **тот же Google Cloud проект**, где работает переходник `ocr-proxy`.
3. В этом проекте должен быть включён биллинг (он уже есть для Vision). Это платный тариф Gemini API:
   Google не использует такие запросы для обучения моделей, и лимиты выше, чем на бесплатном.
4. Скопируйте ключ. **На сервер в РФ его класть не нужно**, он нужен только переходнику.

### Шаг 2. Обновить переходник во Франкфурте
1. Google Cloud Console → Cloud Run → функция `ocr-proxy` → «Edit source» («Изменить и развернуть новую ревизию»).
2. Замените содержимое `index.js` на файл `infra/ocr-proxy/index.js` из репозитория.
3. В переменных окружения функции добавьте `GEMINI_API_KEY` = ключ из шага 1. Остальные переменные не трогайте.
4. Нажмите «Deploy». Распознавание фото продолжит работать как раньше.

### Шаг 3. Проверить переходник (на сервере Beget, в терминале)
Подставьте адрес функции и секрет. Это те же значения, что в `GOOGLE_VISION_ENDPOINT` и `GOOGLE_VISION_API_KEY` в `/opt/buty/.env`:
```bash
curl -s -X POST "https://АДРЕС-ФУНКЦИИ?key=СЕКРЕТ&target=gemini" \
  -H 'content-type: application/json' \
  -d '{"model":"gemini-3.5-flash-lite","input":"Ответь одним словом: привет","store":false}'
```
В ответе должен быть `"status": "completed"` и текст модели. Если пришло `forbidden`, секрет неверный.
Если `gemini is not configured`, не задан `GEMINI_API_KEY` в функции.

### Шаг 4. Переменные на сервере
Добавьте в `/opt/buty/.env` две строки с **теми же значениями**, что у Vision:
```
GEMINI_ENDPOINT="<то же, что GOOGLE_VISION_ENDPOINT>"
GEMINI_API_KEY="<то же, что GOOGLE_VISION_API_KEY>"
```

### Шаг 5. Выкатить код
Попросите Kimi закоммитить изменения и запушить в `main`. Миграция `20261009150000_ai_summary`
(таблица `AiSummary`) применится сама при старте контейнера. После деплоя перезапустите приложение, чтобы оно
подхватило новые переменные из `.env`.

### Шаг 6. Проверить на сайте
Откройте https://buty.app/analyze и вставьте состав, например:
`Aqua, Glycerin, Niacinamide, Squalane, Panthenol, Sodium Hyaluronate, Phenoxyethanol, Parfum, Linalool`.
Через 2–5 секунд под счётчиками появится «Коротко о составе». Повторный разбор того же состава покажет резюме сразу (из кэша).

## Если блок не появляется
Блок показывается всегда: если ИИ-резюме нет, под заголовком «Коротко о составе» будет сводка по правилам
(`buildBasicSummary`). Подпись внизу блока одна для обоих вариантов: «Это не медицинская консультация.»
Жалобы «Нашли неточность?» уходят в фидбэк с префиксом «Резюме ИИ: » для ИИ-резюме и «Сводка: » для сводки без ИИ.

Если ИИ-резюме не появляется (а показывается сводка), посмотрите логи приложения и найдите строки `[ai-summary]`:
- `Gemini ошибка 400 ... thinking_level` — добавьте в `.env` строку `GEMINI_THINKING_LEVEL=""` и перезапустите.
- `Gemini ошибка 404 ... model` — модель переименовали. Укажите актуальную: `GEMINI_MODEL="..."`
  (список: https://ai.google.dev/gemini-api/docs/models). Резюме для новой модели создадутся заново.
- `ответ отклонён проверкой` — модель написала запрещённую формулировку. Это нормально в единичных случаях.
  Если такие строки часто, нужно поправить промпт в `lib/ai-summary/prompt.ts` и увеличить `PROMPT_VERSION`.
  Текущая версия: `PROMPT_VERSION = 2` (живой тон резюме: правила 8–9 и раздел «Тон» с примерами «как не надо /
  как надо» в `SYSTEM_INSTRUCTION`).

## Расходы и статистика
Одно новое резюме — примерно 1,5–3 тыс. входящих токенов и 300–600 исходящих. Платим только за новые уникальные
составы: всё повторное берётся из кэша. Цены модели смотрите на https://ai.google.dev/gemini-api/docs/pricing.

Статистика (SQL в базе):
```sql
SELECT count(*)                 AS резюме,
       sum(hits)                AS выдано_из_кэша,
       sum("inputTokens")       AS входящих_токенов,
       sum("outputTokens")      AS исходящих_токенов
FROM "AiSummary";
```
Жалобы на неточность приходят в обычный фидбэк (`Feedback`): ИИ-резюме — с текстом, начинающимся на «Резюме ИИ:»,
сводка без ИИ — на «Сводка:».
Чтобы пересоздать все резюме (например, после правки промпта), увеличьте `PROMPT_VERSION` в `lib/ai-summary/prompt.ts`.

  пользователя.

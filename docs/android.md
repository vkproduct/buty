# Android-приложение Buty

## Что это и как устроено

Приложение — **Trusted Web Activity (TWA)**: официальная технология Google, при которой приложение открывает сайт https://buty.app на весь экран через движок Chrome, **без адресной строки и браузерных кнопок**. Так устроены Android-приложения многих сервисов, которые развивают в первую очередь сайт.

Что это даёт:

- **100% функций сайта** с первого дня: разбор состава текстом и по фото (камера телефона), каталог ингредиентов и средств, «Моя полка», реакции, напоминания, профиль кожи, вход по ссылке из письма, Pro, кабинет брендов, админка.
- **Обновления без выпуска приложения.** Всё, что выкатывается на сайт (push в `main` → деплой на Beget), сразу появляется в приложении. Новую версию приложения нужно выпускать только при изменении папки `android/` (иконка, ярлыки, название).
- **Вход и сессия общие с Chrome на телефоне**: если пользователь уже вошёл на сайте в Chrome, в приложении он тоже вошёл.

Чем приложение лучше сайта на телефоне:

- иконка на рабочем столе и заставка при запуске;
- **«Поделиться» → Buty** из любого приложения (заметки, мессенджеры, браузер): выделенный текст состава сразу открывается разобранным на `/analyze`;
- **ярлыки** по долгому нажатию на иконку: «Разобрать состав», «Моя полка», «Каталог средств»;
- ссылки `https://buty.app/...` (в том числе ссылка входа из письма) открываются сразу в приложении;
- публикация в Google Play / RuStore — новый канал привлечения.

Если на телефоне нет Chrome или другого браузера с поддержкой TWA (редкость, например часть Huawei), сайт откроется во встроенной вкладке браузера с узкой адресной строкой — всё будет работать.

## Где что лежит

| Файл / папка | Назначение |
| --- | --- |
| `android/` | Android-проект (Gradle). Пакет `app.buty.android`, minSdk 24 (Android 7+), targetSdk 36 (требование Google Play с 31.08.2026) |
| `android/app/src/main/res/values/strings.xml` | название, стартовый адрес (`?utm_source=android_app` — видно в Метрике), настройки «Поделиться» |
| `android/app/src/main/res/xml/shortcuts.xml` | ярлыки на иконке |
| `android/store/` | иконка 512×512 и баннер 1024×500 для страницы в магазине |
| `public/.well-known/assetlinks.json` | подтверждение, что приложение принадлежит сайту. Без него в приложении видна адресная строка |
| `app/manifest.ts` | PWA-манифест сайта: PNG-иконки, ярлыки |
| `.github/workflows/android.yml` | автоматическая сборка APK и AAB на GitHub (до переноса Kimi лежит в `android/ci/android.yml`) |
| `android-keystore/` | **секретный** ключ подписи. Только на вашем компьютере, в git не попадает |

Отпечаток ключа подписи (SHA-256): `67:7F:34:45:2A:56:F0:AD:BE:1E:7A:0E:53:C1:C4:B9:F2:93:1F:D8:6B:57:AD:F0:00:3D:9C:DC:71:63:63:23`

## Шаг 1. Отправить изменения на GitHub (через Kimi)

Попросите Kimi дословно:

> Перенеси файл `android/ci/android.yml` в `.github/workflows/android.yml` (заменив пустой файл с тем же именем) и удали папку `android/ci/`. Затем закоммить и запушь в main: папку `android/`, `.github/workflows/android.yml`, `public/.well-known/assetlinks.json`, `public/icons/`, `public/apple-touch-icon.png`, `app/manifest.ts`, `docs/android.md`, `docs/decisions.md`, `docs/roadmap.md`, `.gitignore`. Папку `android-keystore/` НЕ коммитить — она в .gitignore и содержит секретный ключ. Перед пушем выполни `pnpm typecheck`.

(Файл сборки лежит в `android/ci/`, потому что папку `.github/workflows` Claude менять не может — это защита от изменения CI сторонними инструментами.)

После деплоя проверьте в браузере: https://buty.app/.well-known/assetlinks.json — должна открыться страница с текстом `app.buty.android` и отпечатком выше.

## Шаг 2. Добавить два секрета на GitHub (один раз)

1. Откройте https://github.com/vkproduct/buty → **Settings** → слева **Secrets and variables** → **Actions** → кнопка **New repository secret**.
2. Секрет №1: Name — `ANDROID_KEYSTORE_BASE64`, Secret — всё содержимое файла `android-keystore/buty-release.jks.base64.txt` (открыть в TextEdit, Cmd+A, Cmd+C, вставить). **Add secret**.
3. Секрет №2: Name — `ANDROID_KEYSTORE_PASSWORD`, Secret — пароль из файла `android-keystore/ПРОЧТИ-МЕНЯ.txt`. **Add secret**.

**Обязательно** сохраните копию папки `android-keystore/` в надёжное место (менеджер паролей или зашифрованный архив в облаке). Без этого ключа нельзя выпускать обновления приложения.

## Шаг 3. Собрать приложение

1. GitHub → вкладка **Actions** → слева **android** → справа **Run workflow** → поле версии оставить `1.0.0` (или указать новую, например `1.0.1`) → **Run workflow**.
2. Через 5–8 минут сборка станет зелёной. Откройте её → внизу блок **Artifacts** → скачайте архив `buty-android-…`.
3. В архиве два файла:
   - `buty-1.0.0-N.apk` — для установки на телефон напрямую;
   - `buty-1.0.0-N.aab` — для загрузки в Google Play (RuStore принимает оба формата).

Сборка запускается и сама — при каждом push в `main`, который меняет папку `android/`.

## Шаг 4. Установить на свой телефон

1. Перешлите APK себе на телефон (Telegram «Избранное», Google Диск).
2. Откройте файл → Android попросит разрешить установку из этого источника → **Разрешить** → **Установить**.
3. Запустите Buty. Признак, что всё настроено верно: **нет адресной строки сверху**. Если строка есть — проверьте шаг 1 (assetlinks.json открывается на сайте) и подождите пару минут: Android проверяет связь с сайтом при установке. Помогает удаление и повторная установка.

Что проверить руками: главная, разбор текстом, разбор по фото (кнопка фото → «Камера»), вход по ссылке из письма, «Моя полка», «Поделиться» текстом из заметок → Buty, ярлыки по долгому нажатию на иконку.

## Шаг 5. Публикация в Google Play

1. Аккаунт разработчика: https://play.google.com/console — разовый взнос 25 $. Для новых личных аккаунтов Google требует закрытое тестирование (сейчас — не меньше 12 тестировщиков в течение 14 дней) до открытой публикации; организационный аккаунт (нужен D-U-N-S номер компании) от этого освобождён. Актуальные правила — в Play Console.
2. Создать приложение → загрузить **AAB**. Google включит **Play App Signing** и будет переподписывать приложение своим ключом.
3. **Важно:** Play Console → ваше приложение → **Тестирование и выпуск → Настройка → Целостность приложения (App integrity) → App signing** → скопировать **SHA-256** ключа подписи приложения и добавить его в `public/.well-known/assetlinks.json` вторым значением в `sha256_cert_fingerprints` (через запятую, в кавычках). Попросить Kimi задеплоить. Без этого у установленных из Google Play будет видна адресная строка.
4. Заполнить карточку: иконка `android/store/play-icon-512.png`, баннер `android/store/feature-graphic-1024x500.png`, 2–8 скриншотов телефона, ссылка на политику конфиденциальности, анкета «Безопасность данных» (email, профиль кожи — данные о здоровье, реакции), возрастной рейтинг.
5. **Платная подписка Pro внутри приложения.** Правила Google Play требуют продавать цифровые подписки через Google Play Billing. Сейчас оплата на сайте в mock-режиме; перед включением реальной оплаты (ЮKassa) нужно решить, как Pro продаётся в приложении — проверить актуальные правила Google для пользователей из РФ или не показывать покупку в Android-версии.

## Шаг 6. RuStore (для аудитории в России)

Один раз вручную в https://console.rustore.ru: регистрация разработчика (вход через VK ID), создание приложения с пакетом `app.buty.android` (иконка `android/store/play-icon-512.png`, скриншоты, категория, возрастной рейтинг), затем «Компания → API RuStore → Сгенерировать ключ» — ID ключа и приватный ключ вписать в `android-keystore/rustore.env` вместе с email поддержки.

Дальше версии публикуются скриптом: `node scripts/rustore-publish.mjs <файл.apk> "Что нового"` — токен → черновик версии с описанием → загрузка APK → отправка на модерацию; после одобрения версия публикуется сразу. Загружается APK, подписанный нашим ключом (для AAB RuStore требует загрузить ключ подписи в консоль — не нужно). Отпечаток ключа уже в assetlinks.json. Новая версия должна иметь versionCode больше опубликованной — каждая сборка в GitHub Actions это обеспечивает.

## Как выпустить обновление приложения

Нужно только при изменениях в `android/`. Запустить workflow **android** с новой версией (например `1.1.0`) — номер сборки (versionCode) растёт автоматически — и загрузить новый AAB/APK в магазины. Изменения сайта в приложении появляются сами.

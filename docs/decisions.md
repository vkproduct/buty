## 2026-09-25 — Пакетный менеджер pnpm
- **Решение:** зафиксирован pnpm 12.6.0; все команды в чатах и документации — через pnpm.
- **Причина:** бриф части 0 прямо требует pnpm; единый lockfile, экономия диска.
- **Затронутые части:** все.

## 2026-09-25 — Инициализация Next.js-скелета (часть 1)
- **Решение:** Next.js 14.2.15 (App Router) + TS strict + Tailwind 3.4 + shadcn/ui-компоненты (Button, Card, Input, Badge, Dialog) написаны вручную по стандарту shadcn (Radix Slot/Dialog, cva, clsx, tailwind-merge); дизайн-токены палитры (#5B4BC4/#F7A58C/#E8B84B/#F6F4FB) и стекломорфные тени — в `tailwind.config.ts`; обёртки `GlassCard`, `GradientSection`, `Container` — в `components/ui`; лендинг и заглушки собраны только через обёртки.
- **Причина:** фиксированный стек из брифа; минимум зависимостей (без state-менеджеров); токены и обёртки объявлены один раз для переиспользования во всех частях 2–8.
- **Затронутые части:** 1 (фундамент для 2–8).

## 2026-09-25 — SEO-база: домен-заглушка в metadata
- **Решение:** `metadataBase`/OG/robots/sitemap пока используют домен `https://buty.ru` как константу; sitemap содержит только главную.
- **Причина:** реальный продовый домен не задан; бриф части 4 расширит sitemap динамическими slug'ами — домен вынести в одно место при необходимости.
- **Затронутые части:** 1, 4.

## 2026-09-25 — База ингредиентов (часть 2)
- **Решение:** Prisma 6.19.3 (зафиксирована стабильная ветка, а не 8.0.0-rc); модели `Ingredient`, `Synonym`, `IngredientConflict` (самоссылка m2m, пара нормализуется по id в seed), `Product` + join-таблица `ProductIngredient` с полем `position` (порядок в INCI); enum `EvidenceLevel` (STRONG/MODERATE/LIMITED/ANECDOTAL). Матчинг разделён: чистая `matchTokens(tokens, dictionary)` тестируется без БД, `matchIngredients` подгружает словарь из Prisma. `DATABASE_URL` в gitignored `.env` — локальный PostgreSQL 17, база `buty`.
- **Причина:** бриф части 2; pnpm поставил prisma 8 RC с тяжёлым деревом зависимостей (workerd/pglite) — RC не нужен продовому проекту. Чистые функции для unit-тестов без поднятой БД.
- **Затронутые части:** 2 (фундамент для 3, 4, 6).

## 2026-09-25 — Анализатор состава (часть 3)
- **Решение:** пайплайн разбора вынесен в `lib/analysis/` (`analyze.ts` — оркестрация, `summary.ts` и `advice.ts` — чистые функции; DTO в `types.ts` — общий контракт API и клиента). API — POST-роуты `/api/analyze` и `/api/feedback` (App Router route handlers, `force-dynamic`). Страница `/analyze` — серверный компонент, читающий `?text=`, рендеринг и интерактив — в клиентском `AnalyzeView`. OCR — через интерфейс `OcrProvider` + `MockOcrProvider` (`lib/ocr`), фабрика `getOcrProvider()` — точка подмены на реальный провайдер. Модель `Feedback` (email?, rawToken, createdAt) — для «Сообщить об ингредиенте». Тест на `/api/analyze` мокает `@/lib/prisma` (vitest include расширен на `app/**`).
- **Причина:** бриф части 3; чистые функции и мок Prisma позволяют тестировать API без поднятой БД; mock-адаптер OCR — требование брифа (внешние API только через интерфейс).
- **Затронутые части:** 3 (фундамент для 4 — карточки ингредиентов уже линкуются по slug; 6 — логика конфликтов переиспользуется в «Моей полке»).

## 2026-09-25 — SEO-страницы ингредиентов и продуктов (часть 4)
- **Решение:** детальные страницы `/ingredients/[slug]` и `/products/[slug]` — полностью статические (`generateStaticParams` по всем записям БД + `dynamicParams = false`), metadata через `generateMetadata`, JSON-LD (`MedicalWebPage` / `Product`) инлайн-скриптом. Каталоги `/ingredients` и `/products` — серверные компоненты с фильтрами через `searchParams` (без клиентского стейта), поэтому остаются dynamic — осознанно: фильтры должны быть ссылками, индексируемыми поисковиками. «С чем сочетается» вычисляется из данных: совместные встречи в продуктах минус зафиксированные конфликты. Партнёрская ссылка — поле `Product.partnerUrl` с fallback-заглушкой на поиск Wildberries (`wbSearchUrl` в `lib/seo/labels.ts`). Словари меток вынесены в `lib/seo/labels.ts` (в `analyze-view.tsx` осталась своя копия — предыдущие части не рефакторим).
- **Причина:** бриф части 4; SSG для детальных страниц — трафиковая модель (SEO), а каталоги с searchParams нельзя сделать статическими без потери индексируемых фильтров.
- **Затронутые части:** 4 (фундамент для 7 — партнёрские ссылки; `partnerUrl` заполняется реальными ссылками там).

## 2026-09-25 — Авторизация и «Моя полка» (часть 5)
- **Решение:** NextAuth 4.24 + `@next-auth/prisma-adapter`, database-сессии, email magic-link через кастомный `sendVerificationRequest` → `EmailProvider`-интерфейс (`lib/email/`): без `RESEND_API_KEY`/`EMAIL_FROM` — `MockEmailProvider` (ссылка в консоль), иначе Resend через HTTP API. Страницы `/auth/signin` и `/auth/verify` — свои. Общий `Header` добавлен в root layout как клиентский компонент на `useSession` (через `Providers`/`SessionProvider`) — серверный `getServerSession` в layout переводил бы ВСЕ страницы в dynamic и ломал SSG из части 4. `ShelfItem.customInci` хранит исходный INCI-текст «своего средства»; разбор выполняется сервером на лету через `analyzeText` (часть 3) при рендере полки. Редирект на `/onboarding` — из серверного компонента `/shelf`, если нет `SkinProfile` (без middleware).
- **Причина:** бриф части 5; SSG каталогов — трафиковая модель (часть 4), поэтому сессия в шапке — только клиентская; middleware не добавляли, чтобы не тянуть сессию на все маршруты.
- **Затронутые части:** 5 (фундамент для 6 — статусы и составы полки; для 7 — гейтинг Pro).

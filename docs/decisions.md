## 2026-09-25 — Инициализация Next.js-скелета (часть 1)

## 2026-09-25 — База ингредиентов (часть 2)
- **Решение:** Prisma 6.19.3 (зафиксирована стабильная ветка, а не 8.0.0-rc); модели `Ingredient`, `Synonym`, `IngredientConflict` (самоссылка m2m, пара нормализуется по id в seed), `Product` + join-таблица `ProductIngredient` с полем `position` (порядок в INCI); enum `EvidenceLevel` (STRONG/MODERATE/LIMITED/ANECDOTAL). Матчинг разделён: чистая `matchTokens(tokens, dictionary)` тестируется без БД, `matchIngredients` подгружает словарь из Prisma. `DATABASE_URL` в gitignored `.env` — локальный PostgreSQL 17, база `buty`.
- **Причина:** бриф части 2; pnpm поставил prisma 8 RC с тяжёлым деревом зависимостей (workerd/pglite) — RC не нужен продовому проекту. Чистые функции для unit-тестов без поднятой БД.
- **Затронутые части:** 2 (фундамент для 3, 4, 6).

## 2026-09-25 — Анализатор состава (часть 3)
- **Решение:** пайплайн разбора вынесен в `lib/analysis/` (`analyze.ts` — оркестрация, `summary.ts` и `advice.ts` — чистые функции; DTO в `types.ts` — общий контракт API и клиента). API — POST-роуты `/api/analyze` и `/api/feedback` (App Router route handlers, `force-dynamic`). Страница `/analyze` — серверный компонент, читающий `?text=`, рендеринг и интерактив — в клиентском `AnalyzeView`. OCR — через интерфейс `OcrProvider` + `MockOcrProvider` (`lib/ocr`), фабрика `getOcrProvider()` — точка подмены на реальный провайдер. Модель `Feedback` (email?, rawToken, createdAt) — для «Сообщить об ингредиенте». Тест на `/api/analyze` мокает `@/lib/prisma` (vitest include расширен на `app/**`).
- **Причина:** бриф части 3; чистые функции и мок Prisma позволяют тестировать API без поднятой БД; mock-адаптер OCR — требование брифа (внешние API только через интерфейс).
- **Затронутые части:** 3 (фундамент для 4 — карточки ингредиентов уже линкуются по slug; 6 — логика конфликтов переиспользуется в «Моей полке»).

## 2026-09-25 — SEO-страницы ингредиентов и продуктов (часть 4)
- **Решение:** детальные страницы `/ingredients/[slug]` и `/products/[slug]` — полностью статические (`generateStaticParams` по всем записям БД + `dynamicParams = false`), metadata через `generateMetadata`, JSON-LD (`MedicalWebPage` / `Product`) инлайн-скриптом. Каталоги `/ingredients` и `/products` — серверные компоненты с фильтрами через `searchParams` (без клиентского стейта), поэтому остаются dynamic — осознанно: фильтры должны быть ссылками, индексируемыми поисковиками. «С чем сочетается» вычисляется из данных: совместные встречи в продуктах минус зафиксированные конфликты. Партнёрская ссылка — поле `Product.partnerUrl` с fallback-заглушкой на поиск Wildberries (`wbSearchUrl` в `lib/seo/labels.ts`). Словари меток вынесены в `lib/seo/labels.ts` (в `analyze-view.tsx` осталась своя копия — предыдущие части не рефакторим).
- **Причина:** бриф части 4; SSG для детальных страниц — трафиковая модель (SEO), а каталоги с searchParams нельзя сделать статическими без потери индексируемых фильтров.
- **Затронутые части:** 4 (фундамент для 7 — партнёрские ссылки; `partnerUrl` заполняется реальными ссылками там).

## 2026-09-25 — Авторизация и «Моя полка» (часть 5)
- **Решение:** NextAuth 4.24 + `@next-auth/prisma-adapter`, database-сессии, email magic-link через кастомный `sendVerificationRequest` → `EmailProvider`-интерфейс (`lib/email/`): без `RESEND_API_KEY`/`EMAIL_FROM` — `MockEmailProvider` (ссылка в консоль), иначе Resend через HTTP API. Страницы `/auth/signin` и `/auth/verify` — свои. Общий `Header` добавлен в root layout как клиентский компонент на `useSession` (через `Providers`/`SessionProvider`) — серверный `getServerSession` в layout переводил бы ВСЕ страницы в dynamic и ломал SSG из части 4. `ShelfItem.customInci` хранит исходный INCI-текст «своего средства»; разбор выполняется сервером на лету через `analyzeText` (часть 3) при рендере полки. Редирект на `/onboarding` — из серверного компонента `/shelf`, если нет `SkinProfile` (без middleware).
- **Причина:** бриф части 5; SSG каталогов — трафиковая модель (часть 4), поэтому сессия в шапке — только клиентская; middleware не добавляли, чтобы не тянуть сессию на все маршруты.
- **Затронутые части:** 5 (фундамент для 6 — статусы и составы полки; для 7 — гейтинг Pro).

## 2026-09-25 — Логика «Моей полки» (часть 6)
- **Решение:** совместимость/режим/дубли — чистые функции в `lib/shelf/compatibility.ts` (тесты без БД), загрузка из БД — отдельно в `lib/shelf/data.ts`; «ключевые активы» = категории `active` + `uv-filter`; пара без распознанных активов → правило «разнести по времени суток»; кислоты при наличии ретиноида выносятся из вечернего приёма в notes с чередованием. ## 2026-09-25 — Монетизация (часть 7)

## 2026-09-28 — Каталог ингредиентов: липкая панель фильтров вместо сайдбара
- **Решение:** вертикальный сайдбар `/ingredients` (не помещался в экран при `sticky`, 17 категорий + 4 уровня + поиск) заменён на липкую однострочную панель под шапкой — поиск, сегментированный фильтр доказательности, выпадающий список категорий, сгруппированных по смыслу — «Работают на результат», «Увлажнение и барьер», «Основа формулы» (`lib/seo/ingredient-categories.ts`, `FilterPopover` на нативном `<details>`: работает без JS, с JS закрывается по клику вне/Escape/выбору). Фильтры остались ссылками с `searchParams` (SEO), к ним добавлен якорь `#catalog` — после смены фильтра пользователь сразу видит выдачу. Счётчики фасетные (учитывают остальные активные фильтры), пустые пункты приглушены. Карточка: иконка категории, индикатор доказательности из 4 столбиков (`EvidenceMeter`), название чёрным (розовый — только на hover), концентрация чипом. Длинная выдача без поиска сгруппирована по алфавиту с указателем: кириллица первой строкой, латиница второй, буквы без ингредиентов приглушены. Шкала доказательности приведена к цветам «лестницы» на главной: сильная — success, умеренная — teal, ограниченная — amber (`EVIDENCE_LABEL`, новый `EVIDENCE_META`). Добавлены недостающие метки категорий: texture, emulsifier, ph-buffer. Второй SEO-абзац перенесён в блок «Как мы оцениваем ингредиенты» внизу с легендой шкалы и CTA на разбор.
- **Причина:** сайдбар обрезался по высоте экрана и был визуально монотонным; на мобильных занимал весь первый экран до выдачи.
- **Затронутые части:** 4 (каталог), UI; цвета бейджей доказательности на детальных страницах.

## 2026-09-29 — Каталог продуктов: фильтр по брендам и категориям (мобайл + десктоп)
- **Решение:** ряд чипов-брендов на `/products` заменён на липкую панель под шапкой по образцу каталога ингредиентов: поиск по названию/бренду (`q`) + кнопка фильтров в первой строке, чипы категорий второй строкой (на мобильных — горизонтальная лента, активный чип подкручивается в зону видимости — `ChipRail`; на ширине ≥ xl все категории видны сразу, на узком десктопе — та же лента). Мультивыбор брендов и категорий: повторяющиеся параметры `?brand=A&brand=B&category=serum` (в названиях брендов бывают запятые/апострофы, GET-форма без JS отдаёт именно этот формат; старые ссылки `?brand=X` работают). Логика — чистые функции `lib/products/catalog-filters.ts` (разбор и валидация по справочнику из БД, нормализованные URL, фасетные счётчики, правило индексации) + 12 vitest-кейсов. Панель `ProductFilterSheet` — один компонент на нативном `<details>` + GET-форме: на мобильных нижний лист (категории + бренды, поиск бренда, липкая кнопка «Показать N средств» с живым счётчиком, затемнение, блокировка прокрутки, safe-area), на десктопе — выпадающая панель только с брендами. Выбор черновой до «Показать»: закрыли — откат. Без JS работает как обычная форма. Счётчики фасетные (бренды считаются при выбранных категориях и наоборот), пустые пункты приглушены; при 0 результатов кнопка применения неактивна. Список брендов делится на буквенные группы при > 12 брендах. Категории — в порядке шагов ухода, с иконками (`lib/seo/product-categories.ts`). SEO: посадочные «бренд», «категория», «бренд + категория» индексируются со своим H1/title/canonical («Сыворотки CeraVe — разбор составов»); мультивыбор и поиск — `noindex, follow`, canonical на `/products`. На мобильных у липкой панели нет `backdrop-blur` (иначе `position: fixed` листа привязывается к панели); пока лист открыт, панель поднимается над шапкой (`has-[details[open]]:z-[60]`). На странице продукта бейдж бренда ведёт на отфильтрованный каталог. `pluralRu` вынесен в `lib/utils.ts`.
- **Причина:** бренды будут прибавляться (B2B-модель) — ряд чипов не масштабируется; на мобильных фильтр должен открываться одной кнопкой и не съедать первый экран.
- **Затронутые части:** 4 (каталог продуктов), UI.

Сборка — `.github/workflows/android.yml` (Java 17, Gradle 8.13, подпись из секретов `ANDROID_KEYSTORE_BASE64`/`ANDROID_KEYSTORE_PASSWORD`, versionCode = номер запуска, проверка отпечатка против assetlinks.json), артефакты APK + AAB. ## 2026-10-08 — iOS-приложение: Expo + вход по коду + push через Expo
- **Решение:** приложение на Expo SDK 57 (React Native, TypeScript) в папке `mobile/` того же репозитория; навигация — Expo Router (NativeTabs + Stack с `Stack.Protected`), данные — TanStack Query, токен — Keychain (expo-secure-store). Сборка и отправка в App Store — EAS в облаке, без Xcode. Вход — 6-значный код из письма (HMAC в `MobileLoginCode`, 5 попыток, 5 кодов в час, 10 минут), сессия — отдельная таблица `MobileSession` с SHA-256 токена (не `Session` NextAuth: иначе хэш можно было бы подставить как cookie сайта). `getSession()` принимает `Authorization: Bearer bt_…`, поэтому существующие роуты полки/реакций/напоминаний/профиля/OCR работают для приложения без правок. Сборка полки вынесена из `app/shelf/page.tsx` в `lib/shelf/view.ts` (одна логика для сайта и API). Справочники и подписи — `GET /api/mobile/dictionaries` (правка без релиза приложения). Напоминания — `ExpoPushNotifier`: push на устройства пользователя, мёртвые токены (`DeviceNotRegistered`) удаляются, без устройств или при сбое Expo — `MockNotifier`. Удаление аккаунта — `DELETE /api/mobile/account`. Демо-вход для App Review — `APP_REVIEW_EMAIL`/`APP_REVIEW_CODE`. Pro в приложении только разблокируется (куплен на сайте): нет цен, кнопок и ссылок на оплату, лимит Free описан нейтрально.
- **Причина:** решение владельца — iOS-версия по лучшим практикам, MVP: разбор (текст + фото), каталоги, полка + профиль, push. Expo — рекомендованный командой React Native способ; тот же TypeScript, что на сайте; облачная сборка подходит владельцу без Xcode. Apple отклоняет «обёртки сайта» (правило 4.2) — нативные камера, push и Keychain закрывают это. С 1 апреля 2026 Apple не принимает платежи в российском App Store, а правило 3.1.1 запрещает уводить на оплату вне IAP.
- **Затронутые части:** `mobile/*`, `app/api/mobile/*`, `lib/mobile/*`, `lib/auth.ts`, `lib/shelf/view.ts`, `app/shelf/page.tsx`, `lib/analysis/analyze.ts` (`analyzeMatched`), `lib/reminders/*`, Prisma-схема и миграция, `.env.example`, `tsconfig.json` и `.dockerignore` (исключён `mobile`).
- **Известные ограничения:** нет страницы `/privacy` (обязательна для App Store, ссылка в приложении уже стоит); push зависит от доступности `exp.host` с VPS в РФ; риск правила 3.1.3(b) (Apple может потребовать IAP для Pro вне РФ); приложение проверено сборкой бандла iOS, типами, линтером и веб-рендером с тестовыми данными — на реальном iPhone ещё не запускалось.

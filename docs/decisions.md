## 2026-09-25 — Инициализация Next.js-скелета (часть 1)
- **Решение:** Next.js 14.2.15 (App Router) + TS strict + Tailwind 3.4 + shadcn/ui-компоненты (Button, Card, Input, Badge, Dialog) написаны вручную по стандарту shadcn (Radix Slot/Dialog, cva, clsx, tailwind-merge); дизайн-токены палитры (#5B4BC4/#F7A58C/#E8B84B/#F6F4FB) и стекломорфные тени — в `tailwind.config.ts`; обёртки `GlassCard`, `GradientSection`, `Container` — в `components/ui`; лендинг и заглушки собраны только через обёртки.
- **Причина:** фиксированный стек из брифа; минимум зависимостей (без state-менеджеров); токены и обёртки объявлены один раз для переиспользования во всех частях 2–8.
- **Затронутые части:** 1 (фундамент для 2–8).

## 2026-09-25 — База ингредиентов (часть 2)
- **Решение:** Prisma 6.19.3 (зафиксирована стабильная ветка, а не 8.0.0-rc); модели `Ingredient`, `Synonym`, `IngredientConflict` (самоссылка m2m, пара нормализуется по id в seed), `Product` + join-таблица `ProductIngredient` с полем `position` (порядок в INCI); enum `EvidenceLevel` (STRONG/MODERATE/LIMITED/ANECDOTAL). Матчинг разделён: чистая `matchTokens(tokens, dictionary)` тестируется без БД, `matchIngredients` подгружает словарь из Prisma. `DATABASE_URL` в gitignored `.env` — локальный PostgreSQL 17, база `buty`.
- **Причина:** бриф части 2; pnpm поставил prisma 8 RC с тяжёлым деревом зависимостей (workerd/pglite) — RC не нужен продовому проекту. Чистые функции для unit-тестов без поднятой БД.
- **Затронутые части:** 2 (фундамент для 3, 4, 6).

## 2026-09-25 — Анализатор состава (часть 3)
- **Решение:** пайплайн разбора вынесен в `lib/analysis/` (`analyze.ts` — оркестрация, `summary.ts` и `advice.ts` — чистые функции; DTO в `types.ts` — общий контракт API и клиента). API — POST-роуты `/api/analyze` и `/api/feedback` (App Router route handlers, `force-dynamic`). Страница `/analyze` — серверный компонент, читающий `?text=`, рендеринг и интерактив — в клиентском `AnalyzeView`. OCR — через интерфейс `OcrProvider` + `MockOcrProvider` (`lib/ocr`), фабрика `getOcrProvider()` — точка подмены на реальный провайдер. Модель `Feedback` (email?, rawToken, createdAt) — для «Сообщить об ингредиенте». Тест на `/api/analyze` мокает `@/lib/prisma` (vitest include расширен на `app/**`).
- **Причина:** бриф части 3; чистые функции и мок Prisma позволяют тестировать API без поднятой БД; mock-адаптер OCR — требование брифа (внешние API только через интерфейс).
- **Затронутые части:** 3 (фундамент для 4 — карточки ингредиентов уже линкуются по slug; 6 — логика конфликтов переиспользуется в «Моей полке»).

## 2026-09-25 — SEO-страницы ингредиентов и продуктов (часть 4)
- **Решение:** детальные страницы `/ingredients/[slug]` и `/products/[slug]` — полностью статические (`generateStaticParams` по всем записям БД + `dynamicParams = false`), metadata через `generateMetadata`, JSON-LD (`MedicalWebPage` / `Product`) инлайн-скриптом. Каталоги `/ingredients` и `/products` — серверные компоненты с фильтрами через `searchParams` (без клиентского стейта), поэтому остаются dynamic — осознанно: фильтры должны быть ссылками, индексируемыми поисковиками. «С чем сочетается» вычисляется из данных: совместные встречи в продуктах минус зафиксированные конфликты. Партнёрская ссылка — поле `Product.partnerUrl` с fallback-заглушкой на поиск Wildberries (`wbSearchUrl` в `lib/seo/labels.ts`). Словари меток вынесены в `lib/seo/labels.ts` (в `analyze-view.tsx` осталась своя копия — предыдущие части не рефакторим).
- **Причина:** бриф части 4; SSG для детальных страниц — трафиковая модель (SEO), а каталоги с searchParams нельзя сделать статическими без потери индексируемых фильтров.
- **Затронутые части:** 4 (фундамент для 7 — партнёрские ссылки; `partnerUrl` заполняется реальными ссылками там).

## 2026-09-25 — Авторизация и «Моя полка» (часть 5)
- **Решение:** NextAuth 4.24 + `@next-auth/prisma-adapter`, database-сессии, email magic-link через кастомный `sendVerificationRequest` → `EmailProvider`-интерфейс (`lib/email/`): без `RESEND_API_KEY`/`EMAIL_FROM` — `MockEmailProvider` (ссылка в консоль), иначе Resend через HTTP API. Страницы `/auth/signin` и `/auth/verify` — свои. Общий `Header` добавлен в root layout как клиентский компонент на `useSession` (через `Providers`/`SessionProvider`) — серверный `getServerSession` в layout переводил бы ВСЕ страницы в dynamic и ломал SSG из части 4. `ShelfItem.customInci` хранит исходный INCI-текст «своего средства»; разбор выполняется сервером на лету через `analyzeText` (часть 3) при рендере полки. Редирект на `/onboarding` — из серверного компонента `/shelf`, если нет `SkinProfile` (без middleware).
- **Причина:** бриф части 5; SSG каталогов — трафиковая модель (часть 4), поэтому сессия в шапке — только клиентская; middleware не добавляли, чтобы не тянуть сессию на все маршруты.
- **Затронутые части:** 5 (фундамент для 6 — статусы и составы полки; для 7 — гейтинг Pro).

## 2026-09-25 — Логика «Моей полки» (часть 6)
- **Решение:** совместимость/режим/дубли — чистые функции в `lib/shelf/compatibility.ts` (тесты без БД), загрузка из БД — отдельно в `lib/shelf/data.ts`; «ключевые активы» = категории `active` + `uv-filter`; пара без распознанных активов → правило «разнести по времени суток»; кислоты при наличии ретиноида выносятся из вечернего приёма в notes с чередованием. Реакции: `SkinReaction` с `suspectIngredientIds` (JSON всех распознанных ингредиентов средства), при записи реакции статус средства автоматически → `reacted`. Напоминания: `Reminder` (introduce 28 дн / restock 90 дн), интерфейс `Notifier` + `MockNotifier` (пишет в `NotificationLog`), cron `/api/cron/reminders` защищён заголовком `x-cron-secret` (env `CRON_SECRET`).
- **Причина:** бриф части 6; разделение чистой логики и БД по образцу части 2; внешние каналы — только через интерфейс-адаптер (правило 4).
- **Затронутые части:** 6 (зависимости части 7 — paywall поверх этих функций).

## 2026-09-25 — Монетизация (часть 7)
- **Решение:** `Subscription` (1 на пользователя, enum `Plan` free/pro, status, currentPeriodEnd), `PartnerClick`, `BrandLead`. Платежи — интерфейс `PaymentProvider` + `MockPaymentProvider` (ссылка на `/pricing?mockPayment=…`, paymentId кодирует период и userId); коллбэк `/api/payments/callback` в mock-режиме валидирует формат paymentId и принадлежность пользователю, выдача Pro — `grantPro` (продление от текущего конца периода). Гейтинг — `lib/billing.ts` (чистые `isProActive`/`canAddShelfItem` + `getUserPlan` через Prisma): free — 2 средства (402 PAYWALL в POST /api/shelf), матрица совместимости и режим не вычисляются сервером для free, история реакций — 5 последних. «Экспорт в PDF» — печатная страница `/shelf/export` (только Pro) с автопечатью: браузерный «Сохранить как PDF», без новых зависимостей. Партнёрские переходы — `/go/[productId]` (пишет PartnerClick, редирект на partnerUrl с fallback на поиск WB); история кликов — в `/profile`. Заявки брендов — `/for-brands` + POST `/api/brand-leads`.
- **Причина:** бриф части 7; внешние API — только через интерфейс-адаптер (правило 4); минимум зависимостей — отдельная PDF-библиотека не добавлена.
- **Затронутые части:** 7 (фундамент для 8 — аналитика брендов читает PartnerClick/BrandLead).

## 2026-09-28 — Главная под воронку «разбор → полка → Pro»
- **Решение:** главная больше не повторяет структуру референса. Порядок: hero с бесплатным разбором (вход в воронку) → цифры базы → «Почему этого мало» (боли: конфликты, дубли, порядок) → блок «Моя полка» с интерактивным демо вкладок (`components/shelf-showcase.tsx`, статичные данные) и CTA на регистрацию → три шага Free→Free→Pro → тарифы с выделенным «Pro — год» → доверие (шкала доказательности) → FAQ с возражениями → финальный блок с двумя входами (email для полки через `SignInForm` + форма разбора). Липкая панель ведёт на регистрацию полки. Лимиты Free берутся из `FREE_SHELF_LIMIT`/`FREE_REACTIONS_LIMIT`, цены — из `PLAN_PRICES`. На /shelf для гостя — описание Free/Pro и форма входа вместо устаревшего «Pro-функции скоро».
- **Причина:** цель главной — конверсия в платящих; платную ценность даёт полка (совместимость средств между собой), её нужно объяснить на главной.
- **Затронутые части:** главная, /shelf (гость), SignInForm (проп `cta`).

- **Решение:** токены переведены на «воздушный» стиль: Inter с трекингом −0.02em в заголовках, текст без капса, скругления 8px (кнопки/поля) · 12–16px (карточки) · 24px (крупные блоки), бейджи-пилюли, многослойные мягкие тени (`shadow-glass`, `-lg`, `glow`, `pop`), нейтральная шкала `ink-*` (#222 → #F7F7F7), градиентная основная кнопка `bg-gradient-cta` в зелёном brand, фокус — чёрная обводка. Основной цвет остался зелёным: красный зарезервирован за конфликтами и рисками. Главная: белые секции с тонкими разделителями, цветные блоки — скруглённые карточки внутри контейнера; вкладки демо полки — иконка над подписью с подчёркиванием; FAQ — двухколоночный, с шевронами.

## 2026-09-28 — Палитра: розово-красный brand

## 2026-09-28 — Каталог ингредиентов: навигатор категорий + липкая панель фильтров
- **Решение:** вертикальный сайдбар `/ingredients` (не помещался в экран при `sticky`, 17 категорий + 4 уровня + поиск) заменён на: 1) навигатор категорий над выдачей — три смысловые группы («Работают на результат», «Увлажнение и барьер», «Основа формулы»), чипы с цветной иконкой и счётчиком (`lib/seo/ingredient-categories.ts`); 2) липкую однострочную панель под шапкой — поиск, сегментированный фильтр доказательности, выпадающий список категорий (`FilterPopover` на нативном `<details>`: работает без JS, с JS закрывается по клику вне/Escape/выбору). Фильтры остались ссылками с `searchParams` (SEO), к ним добавлен якорь `#catalog` — после смены фильтра пользователь сразу видит выдачу. Счётчики фасетные (учитывают остальные активные фильтры), пустые пункты приглушены. Карточка: иконка категории, индикатор доказательности из 4 столбиков (`EvidenceMeter`), название чёрным (розовый — только на hover), концентрация чипом. Длинная выдача без поиска сгруппирована по алфавиту с указателем (цифры — «0–9», латиница — «A–Z»). Шкала доказательности приведена к цветам «лестницы» на главной: сильная — success, умеренная — teal, ограниченная — amber (`EVIDENCE_LABEL`, новый `EVIDENCE_META`). Добавлены недостающие метки категорий: texture, emulsifier, ph-buffer. Второй SEO-абзац перенесён в блок «Как мы оцениваем ингредиенты» внизу с легендой шкалы и CTA на разбор.
- **Причина:** сайдбар обрезался по высоте экрана и был визуально монотонным; на мобильных занимал весь первый экран до выдачи.
- **Затронутые части:** 4 (каталог), UI; цвета бейджей доказательности на детальных страницах.

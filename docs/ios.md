# iOS-приложение Buty: от кода до App Store

Код приложения лежит в папке `mobile/`, серверная часть уже есть в основном проекте (`/api/mobile/*`).
Ниже описано, что сделать по шагам. Технические команды выполняются в «Терминале» на Mac или через Kimi.

## Что уже сделано

**Сервер (сайт buty.app):**
- Вход в приложение по 6-значному коду из письма: `POST /api/mobile/auth/request-code` → `verify-code` → токен.
  Код хранится только в виде хэша, на один код даётся 5 попыток, на один адрес — не больше 5 кодов в час, код живёт 10 минут.
- Токен приложения передаётся в заголовке `Authorization: Bearer`. Поэтому все прежние API (полка, реакции,
  напоминания, профиль кожи, OCR) сразу работают и для сайта, и для приложения.
- `GET /api/mobile/shelf` возвращает всю полку одним запросом. Логика вынесена в `lib/shelf/view.ts` и общая со страницей `/shelf`.
- Каталоги для приложения: `/api/mobile/ingredients`, `/api/mobile/products` (поиск, категории, постранично),
  карточки `/api/mobile/ingredients/[slug]` и `/api/mobile/products/[slug]`.
- `GET /api/mobile/dictionaries` отдаёт все подписи и справочники. Если поменять текст на сервере, он появится в приложении без нового релиза.
- **Push-напоминания стали настоящими.** Раньше «Оценить результат» и «Пора докупить» только записывались
  в лог. Теперь, если у пользователя стоит приложение, уведомление уходит на iPhone через Expo Push (`lib/reminders/expo.ts`).
  Если приложения нет, всё работает по-старому.
- `DELETE /api/mobile/account` удаляет аккаунт и все данные пользователя. Apple требует такую возможность обязательно.
- Демо-вход для проверяющих Apple: переменные `APP_REVIEW_EMAIL` и `APP_REVIEW_CODE`.
- Новые таблицы `MobileLoginCode`, `MobileSession` и `PushToken` добавлены миграцией `20261008120000_mobile_app`.
  Она применяется сама при деплое.

**Приложение (`mobile/`):** вкладки «Разбор», «Каталог», «Полка», «Профиль»; разбор текстом и по фото
(камера или галерея, снимок сжимается перед отправкой); карточки ингредиентов и средств; полка со статусами,
совместимостью, режимом (Pro), реакциями и напоминаниями; анкета кожи из 5 шагов с согласием на обработку
данных о здоровье; выход и удаление аккаунта; светлая и тёмная темы; системный шрифт и иконки iOS.

## Шаг 1. Выкатить сервер

1. Попросите Kimi закоммитить изменения и запушить их в `main`. Деплой на Beget пройдёт как обычно,
   миграция базы применится сама.
2. Проверьте, что всё на месте: откройте в браузере `https://buty.app/api/mobile/dictionaries`. Должен открыться длинный текст в фигурных скобках.
3. **Проверьте почту.** На сервере в `.env` должны быть заданы `RESEND_API_KEY` и `EMAIL_FROM`. Без них коды входа
   не придут ни на сайте, ни в приложении: письма будут только в логах сервера.
4. Добавьте в `.env` на сервере демо-доступ для Apple и перезапустите приложение:
   ```
   APP_REVIEW_EMAIL="review@buty.app"
   APP_REVIEW_CODE="246810"
   ```
   Любые 6 цифр подойдут. Войдите в приложение под этим адресом и добавьте на полку 2–3 средства, чтобы проверяющему было что посмотреть.
5. Убедитесь, что напоминания запускаются по расписанию. На сервере должна быть строка в `crontab`
   с `scripts/cron-reminders.sh` (см. README, раздел про VPS).

## Шаг 2. Аккаунты (один раз)

1. **Apple Developer Program:** https://developer.apple.com/programs/enroll/ ($99 в год).
   Понадобится Apple ID с двухфакторной защитой. Можно оформить на себя (физлицо), это быстрее.
   Для организации нужен номер D-U-N-S. Проверка занимает от 1 до 3 дней.
2. **Expo:** зарегистрируйтесь на https://expo.dev. Бесплатного тарифа хватает: облачная сборка, push-уведомления, отправка в App Store.

## Шаг 3. Первая сборка (в Терминале на Mac)

```bash
cd ~/Documents/kimi/Workspaces/Buty/mobile
npm install
npx eas-cli@latest login          # вход в аккаунт Expo
npx eas-cli@latest init           # создаёт проект в Expo и записывает его номер в app.json
```

После `init` в `app.json` появится `extra.eas.projectId`. Закоммитьте это: без номера проекта push-уведомления не заработают.

```bash
npx eas-cli@latest build --platform ios --profile production
```

EAS попросит войти в Apple ID. Отвечайте **Yes** на все предложения создать сертификаты, профиль и
**ключ для push-уведомлений (Apple Push Notifications service key)**. Expo сделает это сам и будет хранить у себя.
Сборка идёт в облаке 15–30 минут. Xcode не нужен.

## Шаг 4. TestFlight: приложение на своём iPhone

```bash
npx eas-cli@latest submit --platform ios --latest
```

EAS создаст приложение в App Store Connect (если его ещё нет) и загрузит туда сборку. Через 10–30 минут
она появится в https://appstoreconnect.apple.com → ваше приложение → TestFlight. Добавьте себя во внутренние тестировщики,
поставьте на iPhone приложение **TestFlight** и установите Buty оттуда. Push-уведомления, камера
и вход проверяются уже на этой сборке.

Следующие версии собираются теми же двумя командами (`build`, затем `submit`). Номер сборки увеличивается сам.

## Риски и как мы их закрыли

- **Оплата Pro.** С 1 апреля 2026 Apple не принимает оплату в российском App Store, а правило 3.1.1 запрещает
  в приложении цены, кнопки и ссылки на оплату в обход Apple. Поэтому в приложении нет ни слова о покупке.
  Пользователь с бесплатным тарифом видит лимиты нейтрально («до 2 средств на полке»), а Pro, купленный на сайте, включается сам.
  Остаётся риск по правилу 3.1.3(b): Apple может попросить добавить покупку Pro внутри приложения для других стран.
  Если так случится, добавим подписку через Apple только для стран за пределами России.
  Российские пользователи по-прежнему будут платить на сайте.
- **Push с сервера в РФ.** Сервер отправляет уведомления на `exp.host` (Expo). Если этот адрес будет недоступен с Beget,
  напоминание запишется в лог, как раньше, и ничего не сломается. Проверить доступ можно на сервере:
  `curl -I https://exp.host`.
- **Вход.** Код приходит письмом через Resend. Если письма не доходят, пользователь не сможет войти ни на сайт, ни в приложение.
  Проверьте это до публикации (шаг 1.3).
- **Удаление аккаунта** есть в «Профиле» (обязательно для App Store и соответствует 152-ФЗ).

## Как устроен вход (для разработчика)

1. `request-code` генерирует 6 цифр, сохраняет HMAC-SHA256 от `email:код` (ключ `NEXTAUTH_SECRET`) и шлёт письмо.
2. `verify-code` сверяет хэш за постоянное время, создаёт пользователя (как при входе по ссылке на сайте) и `MobileSession`
   с SHA-256 от случайного токена `bt_…`. Сам токен возвращается приложению один раз и лежит в Keychain iPhone.
3. `getSession()` (`lib/auth.ts`): если есть `Authorization: Bearer bt_…`, ищется мобильная сессия, иначе cookie NextAuth.
   Сессия живёт 180 дней и продлевается при использовании. Выход и удаление аккаунта гасят токен на сервере.

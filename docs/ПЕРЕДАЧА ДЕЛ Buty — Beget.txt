# Buty — передача дел: переезд с Vercel на собственный сервер (Beget)

## Что изменилось
Сайт buty.app больше не живёт на Vercel: из России Vercel недоступен (блокируются *.vercel.app и IP Vercel, в том числе на своём домене). Прод переехал на VPS Beget в России.

- Сервер: Beget VPS, Ubuntu 24.04, IP 62.217.180.33
- Домен: buty.app (регистратор Porkbun). A-записи @ и www → 62.217.180.33. TXT/MX-записи не трогать.
- Стек на сервере: docker-compose.prod.yml = app (Next.js) + db (Postgres 16, volume db-data, наружу не открыт) + caddy (автоматический HTTPS Let's Encrypt, редирект www → bare).
- Код: /opt/buty (git clone репозитория github.com/vkproduct/buty, ветка main).
- Секреты: /opt/buty/.env ТОЛЬКО на сервере, в git его нет и не будет. Там: DOMAIN, NEXT_PUBLIC_SITE_URL, NEXTAUTH_URL, NEXTAUTH_SECRET, POSTGRES_PASSWORD, CRON_SECRET, ADMIN_EMAILS, EMAIL_FROM, RESEND_API_KEY (пока пустой), PAYMENTS_PROVIDER=mock. Позже добавится GOOGLE_VISION_API_KEY.
- Доступ: ssh deploy@62.217.180.33 только по ключу ~/.ssh/id_ed25519 с Mac владельца. Вход под root и по паролю отключён (scripts/server-setup.sh).
- Docker Hub из РФ заблокирован, в /etc/docker/daemon.json прописаны зеркала dockerhub1.beget.com и mirror.gcr.io.
- База теперь локальная на сервере. Supabase больше не используется (данные переносятся отдельно, если нужно).
- При каждом старте контейнера app entrypoint сам выполняет prisma migrate deploy и db seed (идемпотентно). Отдельно запускать миграции на сервере не нужно.

## Как теперь выкатывать изменения
1. Работаешь как обычно, проверяешь: pnpm typecheck && pnpm test.
2. Коммитишь только нужные файлы (git add по именам) и пушишь в main: git push.
3. Деплоишь на сервер одной командой с Mac:
   ssh deploy@62.217.180.33 'cd /opt/buty && git pull --ff-only && docker compose -f docker-compose.prod.yml up -d --build && docker image prune -f && docker compose -f docker-compose.prod.yml ps'
   Сборка идёт 5–15 минут, простой сайта — около минуты при перезапуске контейнера.
   Запасной вариант той же операции: ./scripts/deploy.sh deploy@62.217.180.33 (он не чистит старые образы, раз в пару недель выполняй docker image prune -f).
4. Проверка после деплоя:
   curl -fsS https://buty.app/api/health   → {"ok":true,"db":"up"}
   Плюс открыть buty.app в браузере.

## Правила
- Никогда не делать git push --force в main: сервер делает git pull --ff-only, переписанная история сломает деплой.
- Никогда не коммитить .env и не перезаписывать /opt/buty/.env на сервере. Новую переменную добавлять так:
  ssh deploy@62.217.180.33 'cd /opt/buty && echo "ИМЯ=значение" >> .env && docker compose -f docker-compose.prod.yml up -d --force-recreate app'
- Новая переменная NEXT_PUBLIC_* вшивается при сборке: её нужно добавить и в .env, и в build.args в docker-compose.prod.yml, и деплоить с --build.
- Без необходимости не трогать Caddyfile, docker-compose.prod.yml, Dockerfile, docker-entrypoint.sh, scripts/server-setup.sh.
- Внешние сервисы выбирать с учётом того, что сервер в России. OpenAI, Anthropic и Gemini напрямую из РФ недоступны. Для LLM — YandexGPT/GigaChat или переходник за рубежом.
- Правила проекта из «ПРОЕКТ Buty.ru.txt» в силе: стек фиксирован, адаптеры с mock по умолчанию, решения записывать в docs/decisions.md.

## Полезные команды на сервере (ssh deploy@62.217.180.33, затем cd /opt/buty)
- Статус: docker compose -f docker-compose.prod.yml ps
- Логи приложения: docker compose -f docker-compose.prod.yml logs -f --tail=100 app
- Перезапуск: docker compose -f docker-compose.prod.yml restart app
- Откат на прошлый коммит: git checkout <sha> && docker compose -f docker-compose.prod.yml up -d --build   (после исправления вернуться: git checkout main && git pull)
- Бэкап базы вручную: bash scripts/backup.sh   (файлы в /opt/buty-backups)
- Ссылка для входа, пока почта в mock-режиме (нет RESEND_API_KEY):
  docker compose -f docker-compose.prod.yml logs app | grep -o "https://buty.app/api/auth/callback[^ ]*" | tail -1
